# 10 AI 模块：从配置到集成

**目标**：理解平台 AI 能力的全貌，完成开箱配置的三步，掌握三个使用入口与两种业务集成方式，并知道哪些边界不能碰。

**前置**：[02 从零跑起来](./02-get-it-running.md)（要有一个能登录的环境）；理解租户隔离（[06 章](./06-multi-tenant-isolation.md)）与套餐白名单（[docs/plan_billing.md](../plan_billing.md)）会让"为什么有的租户用不了 AI"变得显然。

---

## 10.1 能力全景

AI 模块由五块组成，全部围绕两张核心思路：**模型接入与业务解耦**（提供商是数据，不是配置文件）、**告警/分析只产出结构化事实**（文案归前端 i18n，模型只生成指定部分）。

| 能力 | 入口 | 一句话说明 |
|---|---|---|
| 模型提供商 | 管理页「AI 提供商」 | 一行 = 一个 OpenAI 兼容端点（云端 API 或本地 Ollama）；api_key 加密落库 |
| 流式对话 | 分析页 → AI 助手 | SSE 实时推送增量 token；同步响应携带完整回复 |
| 知识库 RAG | 管理页「知识库」 | 文档切片 → 向量化（pgvector）→ 检索注入对话上下文 |
| 用量配额 | 套餐配额 `AI_TOKENS` | 每次调用记账（`sys_ai_usage_logs`），月度配额超限拒绝 |
| 安全与异常洞察 | 分析页卡片 | 规则预筛审计明细（深夜操作/失败集中/口令尝试），LLM 只写总评 |

## 10.2 配置三步（跑通的前置）

1. **数据库装 pgvector**：知识库检索依赖 `vector` 扩展。服务启动时会自动 `CREATE EXTENSION IF NOT EXISTS vector` 并补列（需要超级用户权限；失败只降级 RAG，其余功能不受影响）。Docker 部署换 `pgvector/pgvector:pg16` 镜像即可。
2. **配置提供商**：管理页「AI 提供商」新建一条——云端填 OpenAI 兼容 `baseUrl` + `apiKey`（DeepSeek/通义等均兼容），本地填 Ollama 主机端口（key 留空）。勾选「默认提供商」，聊天与定时任务在未指定时都用它。
3. **放行租户**（仅多租户场景需要）：租户访问 AI 端点受两层门禁——**套餐模块白名单**要有 `AI` 行（套餐管理里给目标套餐勾选），**配额**可选配 `AI_TOKENS`（不配 = 不限量）。已部署实例别忘了先做一次「接口同步」，否则新端点在 Api 表缺失、租户闸门 fail-closed 403。两步的完整操作步骤与 403 报错甄别表见 [docs/ai_module.md](../ai_module.md) 的「新部署注意：给租户放行 AI」一节。

平台管理员（tenant_id=0）不受白名单与配额限制。

## 10.3 三个使用入口

- **AI 助手（聊天页）**：选知识库后提问，命中片段会自动注入对话上下文；增量 token 走 SSE `ai_chat_chunk` 实时渲染，最终以响应为准。
- **知识库（管理页）**：粘贴纯文本或上传文件（txt/md/docx/pdf 等，后端抽取文本）→ 切片向量化入库。换 embedding 模型后用「任务管理」建 `ai_doc_reindex` 任务全量重算。
- **分析页（安全与异常洞察）**：规则预筛近 24h 审计明细里的行为模式（疑似口令尝试/深夜操作/失败集中/敏感操作），输出结构化告警 + LLM 总评。
- **智能问数（多轮）**：支持追问——"那只看 admin 的"、"换成按天分组"，模型结合对话历史理解指代后重新生成 SQL；每轮 SQL 仍过全部护栏。

## 10.4 集成到业务

- **脚本里调模型**：脚本（JS/Lua）内置 `ai` 模块——`ai.chat(content)` / `ai.chatWith(providerId, content)`。实体钩子、定时脚本里都能用（例如 `user.after_create` 生成欢迎语）。每次调用自动记用量。
- **定时 AI 任务**：`ai_audit_digest` 是系统常驻任务（每日 08:00），聚合昨日审计生成中文日报并站内信投递平台用户。自定义 AI 批处理任务可照此模式注册新的任务类型。

## 10.5 边界与注意

- **数据出域**：对话内容与知识库文本会发送到你配置的模型端点。对政企/等保场景，用本地 Ollama 提供商可让数据不出内网；租户是否可用 AI 由套餐白名单控制。
- **智能问数的租户边界**：租户用户只能查 6 张本租户数据表，生成的 SQL 必须自带 `tenant_id = 自身ID` 谓词（缺失即拒绝，fail-closed）；平台级表对租户不可见。
- **告警零文案架构**：洞察告警只回传结构化事实（severity/type/facts），文案由前端 i18n 模板按界面语言渲染——**后端永远不要生成人类可读的告警文案**，否则多语言界面必然不一致。LLM 总评按请求语言生成。
- **无告警不调模型**：洞察在规则筛不出信号时直接给确定性结论，不浪费模型调用，也不让模型编造异常。
- **demo 用 mock**：`.zcode/tmp/mock_llm.py` 是一个 OpenAI 兼容的 mock 服务（echo 对话 + 可断言的 embeddings），本地无真实 key 也能全链路演示。
